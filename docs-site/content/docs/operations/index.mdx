Once your services run, this section covers the day-to-day work: reading what they print, seeing how much CPU, memory, disk and network they use, growing the cluster with more servers, getting told when something breaks, and keeping LogiStack itself up to date. It also covers moving an existing Dokploy or Coolify server to LogiStack.

![The Monitoring page, with cluster CPU, memory, disk and network charts over the last 24 hours](/screens/monitoring.webp)

## Where things live

| You want to | Go to |
| --- | --- |
| Read a service's output, or run a command inside it | The service's **Logs** and **Terminal** tabs |
| Ship logs to Loki, Datadog, OpenTelemetry or syslog | **Integrations** › **Log drains** |
| See one service's CPU, memory, network and disk I/O | The service's **Metrics** tab |
| See every server's CPU, memory, disk and network | **Monitoring** › **Overview** |
| Add, label, drain or remove a server | **Monitoring** › **Nodes** |
| Set alert thresholds and metric retention | **Monitoring** › **Settings** |
| Check sites, ports and certificates from outside, publish a status page | **Monitoring** › **Uptime**, **Incidents** and **Status pages** |
| Send events to Slack, email, Telegram and others | **Integrations** › **Notifications** |
| See what each project consumes | **Monitoring** › **Usage**, or **Usage** on a project |
| Update LogiStack | **Settings** › **Updates** |
| Move from Dokploy or Coolify | **Settings** › **Migrate** |

A service is one thing LogiStack runs inside an environment: an app built from Git, a published Docker image, a managed database, a Compose stack, an object storage server, a game server or a web server. This section explains each source, how a deployment rolls out, and the settings you change afterwards. Read it when you add something new to a project or need to change how an existing service builds and runs.

## How services are organized

Every service lives in an environment, and every environment lives in a project. A new project starts with a **Production** environment. Services in the same environment share a private network and reach each other by service name, so an app reaches a database called `postgres` at `postgres:5432`.

LogiStack stores the desired state of each service in Postgres. A worker converges Docker Swarm and the Caddy proxy to that state, so every operation is safe to repeat.

## Add a service

<Steps>
<Step>

### Open the project

Select **Projects** in the sidebar, then open your project. Pick the environment from the environment list.

![The Storefront project page with its Production environment and the New service button](/screens/project.webp)

</Step>
<Step>

### Start the wizard

Select **New service**. The **Choose a source** step lists every kind of service.

![The New service wizard on its Choose a source step, listing Git repository, Docker image, Database, Docker Compose, Object storage, Game server, Web server and Templates](/screens/service-new.webp)

</Step>
<Step>

### Pick a source and follow the steps

Choose a source and select **Continue**. Each source has its own steps, described in the pages below. The last step is always **Review**: nothing is created until you select **Create and deploy**.

</Step>
</Steps>

## After the first deployment

Each service page has tabs for its day-to-day work. The ones in this section:

- **Deployments**: history and live build logs. See [Deployments](./deployments.mdx).
- **Environment**: variables and secrets, including references to [external secrets](./external-secrets.mdx) in Vault, Infisical or 1Password. See [Environment variables](./environment-variables.mdx).
- **Settings**: source, build, resources, healthcheck, ports and placement. See [Service settings](./service-settings.mdx).

For the organization-wide build setup, see [Build platforms](./build-platforms.mdx) and [Registries](./registries.mdx). To give every pull request its own copy of a project, see [Preview environments](./preview-environments.mdx). To scale a service with its load, see [Autoscaling](./autoscaling.mdx). To stop a whole project without deleting it, see [Archive a project](./archive-projects.mdx).
